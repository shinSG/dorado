# Dorado 个人学习工作台产品调整方案 V1

## 1. 产品定位与边界

Dorado 面向个人 Rust 学习者，提供简洁直接的在线练习，以及快速准备本机开发环境的能力。主定位是“Rust 学习与实践工作台”。

两条路径共用课程内容：

- 在线学习：打开课程 → 完成练习 → 获取反馈 → 保存进度 → 继续学习。
- 本机实践：选择环境方案 → 下载并执行安装脚本 → 验证工具链 → 导出阶段项目到本机练习。

环境部署是常驻一级功能，不是在线学习前置条件。此处部署指学习者的 Rust 开发环境；平台服务自身的部署属于维护文档，不混入学习界面。

当前按一个应用实例对应一个个人学习空间设计。暂不建设注册、登录、个人资料、权限、排行榜、评论和运营后台。学习记录仍需持久化、备份和恢复；“没有账号”不等于“没有进度”。

## 2. 当前基础与本轮设计修正

当前已有 18 章 Markdown、练习种子数据、FastAPI/SQLite、Docker Rust 运行器。上一轮前端已改为紧凑首页、单题工作台、浏览器草稿、结果分区和章节完成后的进度保存。

需要准确区分现状与目标：

- `/setup` 页面代码和环境 API 仍存在，但路由和导航入口已移除。后续恢复入口并改造流程。
- 环境检测当前运行于后端机器，不能据此判断远程浏览器所在电脑已安装 Rust。
- 当前自动完成由前端调用进度 API，解锁也有前端推导；目标是统一由后端计算。
- 现有题型仍共用代码编辑器，预测输出尚不是独立答案输入；自由题、修复题的判定仍较宽松。
- 当前仍保留账号代码和历史身份字段；个人模式需进一步统一数据来源。

本文为待实施设计，不代表这些目标已交付。

## 3. 信息架构

| 页面 | 用户目的 | 主要内容 | 主操作 |
| --- | --- | --- | --- |
| 学习首页 `/` | 快速回到上次任务 | 继续练习、紧凑课程列表、待复习入口 | 继续练习 |
| 学习工作台 `/chapter/:slug` | 完成一个具体任务 | 题目、必要知识、编辑器、评测反馈 | 提交练习 |
| 环境部署 `/setup` | 快速准备指定电脑的 Rust 环境 | 系统选择、安装方案、脚本、验证 | 获取安装脚本 |
| 复习 `/review` | 处理未掌握的题目 | 待重练列表、错误摘要 | 开始复习 |

顶部固定保留“学习”“环境部署”。复习先作为首页次级入口，有足够记录后再决定是否独立导航。备份/恢复放在次级菜单，无需建立账号式设置中心。

## 4. 学习首页与工作台

### 4.1 首页

首次访问突出“开始第一题”，同时提供次级入口“准备本机环境”。后续优先展示上次未完成练习及章节名称；全部完成时明确显示“回顾课程”。

课程列表展示章节顺序、标题、一行摘要和状态。首页只保留个人章节完成数，不展示全平台提交量和全局通过率。未解锁章节可预览学习目标；是否允许提前阅读与是否允许计入通关分开定义。

### 4.2 工作台布局

桌面默认采用双栏：左侧题目与按需展开的知识、提示；右侧当前题的编辑器、运行/提交操作及结果区。可收起目录位于页面左侧。一页只挂载当前题的编辑器。

手机使用“题目 / 代码与结果”标签切换，提交后切换到结果所在区域。主按钮始终能辨认；不依赖鼠标悬停展示必要操作。

题目先说明“实现什么”和“如何判断正确”。长篇章节保留为相关知识，逐步把文章拆成可对应练习的小节，避免把短说明误当成完整教学。

### 4.3 题型交互

| 题型 | 输入方式 | 判定方式 |
| --- | --- | --- |
| 编程题 | 可编辑代码 | 输出或函数测试，覆盖边界条件 |
| 修复题 | 有错误的初始代码 | 编译成功且行为满足用例 |
| 填空题 | 标记可编辑区，支持跳转下一个空 | 编译及行为测试；不依赖少数占位符字符串 |
| 预测输出 | 只读代码 + 多行答案框 | 服务端比较答案；提交前不提供直接运行揭晓答案 |
| 测试题 | 函数/模块编辑区 | 指定测试集全部通过，保留失败摘要 |

公开示例可帮助调试；隐藏测试不通过练习详情 API 返回。涉及具体语法教学目标时，增加明确的题目约束或专项验证，不能仅凭输出相同认定掌握某种语法。

### 4.4 操作与反馈

- 代码草稿按练习和题目版本保存，刷新、切题后恢复；保存失败提示复制备份。
- 运行仅检查代码，不改变通过状态；提交才产生评测记录。
- 分别呈现排队、编译、运行、评测、完成状态；未建设后端阶段事件前只显示真实可确认的“处理中”。
- 输出、编译错误、评测反馈使用独立字段；包含 HTML 字符的程序输出按纯文本展示。
- 通过后保留代码和结果，显示“下一题”；最后一道题后优先引导未完成题，否则进入章节完成区。
- 全部必做题通过后，由后端事务更新章节进度并计算下一章状态。失败时可重试，不重复创建通过记录。
- 重置需要页内确认；请求进行中锁定相应操作，避免重复提交或旧响应覆盖新题。
- 提示逐层展开：概念 → 定位 → 思路。参考答案在主动展开后提供，并将“看过答案”与“独立完成”区分记录。

## 5. 快速环境部署

### 5.1 核心流程

采用“选择 → 安装 → 验证”三个步骤。首屏展示系统选择、推荐方案和一个主按钮，详细工具列表默认收起。

1. 选择目标系统。浏览器识别仅用于预选，允许手动修正；首期正式支持 macOS 与 Debian/Ubuntu。未验证的发行版明确标为暂不支持，不回退到错误脚本。
2. 选择方案并展示即将安装的内容，提供“下载安装脚本”“复制执行命令”和脚本预览。
3. 在目标电脑终端执行，脚本逐项显示检测、安装、跳过、失败结果。
4. 执行验证，生成结构化报告；页面导入报告后显示通过项、失败项和下一步操作。
5. 完成后进入“运行第一个 Rust 程序”或继续阶段项目。

首期定位为“复制命令后快速部署”。普通网页不能直接在用户电脑安装软件，不能显示虚假的网页实时安装进度。若未来需要网页内启动及实时日志，再单独设计本地助手。

### 5.2 安装方案

| 方案 | 内容 | 默认行为 |
| --- | --- | --- |
| 基础学习，推荐 | 必需编译工具、rustup、课程兼容的 stable 工具链、rustfmt、clippy | 满足入门练习即可 |
| 项目实践 | 基础方案 + 明确选中的项目工具 | 按需选装，不默认全装 |
| 自定义 | 展开组件及其用途 | 由使用者明确选择 |

nightly、cargo-watch、cargo-nextest 等不作为基础学习必需项。已有环境应复用，重复执行能跳过已满足项；不无提示修改已有默认工具链。macOS 工具安装需要外部安装器完成时，明确暂停并给出继续步骤。

### 5.3 检测范围与报告

页面明确区分“目标电脑”和“Dorado 服务所在机器”。当前 `/api/env/detect` 仅可用作后者的检测，不能作为远程电脑报告。

首期提供可下载检测脚本，输出 `schema_version`、`checked_at`、`os`、`arch`、工具版本、检查项和失败原因。用户导入 JSON 后展示检测时间，旧报告不显示为实时状态。报告仅包含必要工具信息，不包含账号、令牌或完整环境变量。

验收以实际编译并运行一个最小程序为准，不能仅根据 `rustc --version` 显示成功。脚本中的可选工具失败不得被静默吞掉，应标记“基础环境就绪，可选项失败”。网络失败支持重试失败步骤，且保留已有安装成果。

## 6. 视觉规范

统一中性深色背景、橙色主操作、绿色通过状态。减少大横幅、装饰性图标、渐变和重复卡片；通过留白、细分隔线和字号建立层级。

学习页优先给编辑器空间，部署页优先给步骤和命令空间。每个阶段只有一个明显主操作；次级操作使用文本按钮。正文保证可读对比度，错误不只靠颜色表达。支持键盘焦点、折叠状态说明、窄屏无横向溢出及减少动效偏好。

## 7. 数据、接口与模块调整

保留现有 FastAPI 单体及 SQLite，先按职责拆分服务，无需立即引入微服务或复杂消息设施。

- `ContentService`：Markdown、小节、练习定义、题型与测试版本。以稳定业务 ID 导入更新，避免修改种子后已有数据库不更新。
- `LearningService`：个人进度、通过记录、解锁、复习。章节关系是 Chapter → Exercise → Submission，Chapter → Progress；对章节进度增加唯一约束。
- `JudgeService`：编译、执行、测试、输出限额和超时清理。先使用有界执行并发；需要跨进程调度时再引入持久化任务队列。
- `EnvironmentService`：安装方案、脚本模板、检测报告校验。从 `sandbox.py` 分离环境安装逻辑。

建议新增 `content_version`、`exercise_version`、独立 `feedback`、`exit_code`、`timed_out`、`duration_ms` 等字段。预测输出提交使用 `answer` 字段，代码题使用 `code`，由后端根据题型校验。不要继续让 `solution_code` 同时承担参考代码和期望输出。

进度与提交统一使用固定个人空间；移除前端对旧 Token 和用户查询参数的依赖。历史数据迁移先备份，若已有多个身份的数据，显式选择迁入的记录，不能直接混合或删除。

部署接口建议新增 `GET /api/env/profiles`、按系统和方案下载脚本、`POST /api/env/reports/validate`；保留旧下载接口的兼容期。学习接口提交结果同时返回章节状态及下一任务，前端不再独立决定完成与解锁。

## 8. 分阶段交付与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| A：入口与布局 | 恢复 `/setup` 和顶部环境部署入口；统一三步式布局 | 首页、练习、部署互通；窄屏可操作；无账号前置要求 |
| B：部署闭环 | 系统/方案选择、幂等脚本、验证报告导入 | 支持系统完成最小程序验证；重复安装可跳过；网络/权限失败有具体反馈；不误报目标设备 |
| C：学习可信 | 题型专属输入、结构化评测、后端进度计算、个人数据迁移 | 无效代码不能通关；预测输出提交答案；最后必做题通过自动解锁；刷新进度一致 |
| D：学习连续性 | 版本化草稿、提交历史、分级提示、错题重练、项目导出 | 切题不丢草稿；能恢复最近任务；导出项目可按说明本机运行 |

各阶段补充对应测试：前端关键流程及响应式检查；后端题型、进度及失败路径测试；环境脚本在声明支持的系统实际验证。未验证的平台不能显示为正式支持。

个人产品的验收指标优先采用任务能否完成：从首页进入上次练习一步可达；部署三步内拿到正确脚本；刷新草稿不丢失；失败能定位并重试；正确提交与进度一致。首期无需外部埋点或运营分析系统。

## 9. 本轮实施建议

先完成 A、B，恢复并做好用户明确需要的快速环境部署；同时保留上一轮单题工作台。随后完成 C，使评测和进度可信，最后补齐 D。AI 助教、多用户体系及社交功能暂不进入本轮范围。
